이 매뉴얼은 프로그램을 처음 보는 평가자와 센터 담당자가 문의 없이 설치하고 써 볼 수 있도록 쓴 것이다. 순서대로 따라 하면 된다.

2실행1분

이 문서는 같은 내용의 사용자_매뉴얼.html 로도 들어 있다(더블클릭하면 브라우저에서 표가 그대로 보인다). 프로그램 화면 바닥의 "도움말"을 누른 뒤 "사용 설명서 열기"를 눌러도 같은 문서가 새 창에서 열린다.

미리 알아 둘 것 세 가지:

  • 참가자의 Windows PC 에서 제출 zip(이전 화면 판)을 풀어 run.bat 으로 실행해 정상 동작을 확인했다(2026-11-17). 지금의 3차 화면 판(2026-11-18 저녁에 "한 화면에 한 가지"로 다시 만들고 자세한 것은 상세 페이지로 옮긴 화면)은 제출 전에 Windows 에서 다시 확인할 예정이다. 개발 기기(macOS)에서는 3차 화면 판을 규칙 모드와 LLM 모드(실제 Claude API 호출)로 끝까지 돌려 확인했다. 센터 PC 의 보안정책 아래에서는 돌려 보지 못했다. 막히는 곳이 있으면 6절의 표를 본다.
  • 시험한 파이썬 판은 3.9.6 과 3.14.5 다. 그보다 새 판(3.15 이상)이나 "Python install manager"로 설치한 파이썬에서는 돌려 보지 못했다. 새 판에서 문제가 있으면 "Windows installer (64-bit)" 3.14.x 를 설치한다.
  • 프로그램에 함께 든 센터 CSV(data\sample_center 폴더)는 명세서대로 만든 가상 데이터다. 실제 제주빅데이터센터 데이터가 아니다.

1. 파이썬 설치 (Windows 11)

이 프로그램은 파이썬만 있으면 된다. 따로 설치하는 패키지는 없다.

이미 파이썬 3.9 이상이 설치돼 있으면 2절로 간다. 모르겠으면 그냥 2절의 run.bat 을 실행해 본다. 파이썬이 없으면 검은 창에 "Python 3.9 or newer was not found on this PC." 라고 나온다. 그때 아래를 한다.

순서할 일
1브라우저에서 https://www.python.org/downloads/windows/ 를 연다.
2"Windows installer (64-bit)" 를 눌러 설치 파일을 받는다. 판은 3.14.x 를 권한다(이 프로그램을 시험한 판이다. 3.9 이상이면 돌도록 만들었다).
3받은 파일(python-3.x.x-amd64.exe)을 더블클릭한다.
4설치 첫 화면 맨 아래의 "Add python.exe to PATH" 에 체크한다. 이것을 빼먹으면 프로그램이 파이썬을 찾지 못할 수 있다.
5"Install Now" 를 누른다. 끝나면 "Close" 를 누른다.
  • 파이썬 공식 사이트가 "Python install manager"라는 다른 설치 방식을 함께 안내할 수 있다. 이 매뉴얼은 위의 "Windows installer (64-bit)" 기준으로 썼고, install manager 로 설치한 파이썬에서는 run.bat 을 돌려 보지 못했다.
  • Microsoft Store 의 파이썬을 써도 되지만, Store 에서 파이썬을 설치하지 않은 상태에서는 python 을 치면 Store 창만 열린다. run.bat 은 이 경우를 "파이썬 없음"으로 보고 안내문을 띄운다.

2.2 보안 경고 창이 뜰 때

인터넷에서 받은 zip 에서 꺼낸 파일이라 Windows 가 경고를 띄울 수 있다. 프로그램은 이 PC 안에서만 돌고(주소 127.0.0.1) 무엇도 설치하지 않는다.

뜨는 창조치
"Windows의 PC 보호" (파란 창)"추가 정보"를 누른 뒤 "실행"을 누른다.
"파일 열기 - 보안 경고""실행"을 누른다.
"Windows Defender 방화벽에서 이 앱의 일부 기능을 차단했습니다"이 프로그램은 다른 PC 의 접속을 받지 않으므로 뜨지 않도록 만들었다. 뜨더라도 "취소"를 눌러도 프로그램은 쓸 수 있다.
센터 보안 프로그램이 run.bat 이나 python.exe 실행을 막음이용자가 풀 수 없다. 센터 담당자에게 알린다(7.5절).

2.3 브라우저가 열리지 않을 때

검은 창에 표시된 http://127.0.0.1:숫자/ 주소를 마우스로 끌어 복사한 뒤 Chrome 이나 Edge 주소창에 붙여 넣는다. 숫자(포트)는 실행할 때마다 달라지므로 그때 창에 나온 주소를 쓴다.

검은 창 안을 마우스로 끌어 글자를 고른 채로 두면(창 제목에 "선택"이 붙는다) 일부 PC 에서는 프로그램이 멈춘 것처럼 보일 수 있다. 복사한 뒤 Enter 나 Esc 를 한 번 눌러 고르기를 푼다.

2.4 끝내기와 다시 실행

  • 끝낼 때: 화면 오른쪽 위 "처음부터"를 눌러 결과를 지운 뒤(4절 5단계) 검은 창을 닫는다.
  • 다시 실행하면 주소의 숫자가 바뀐다. 예전에 열어 둔 브라우저 탭에는 머리 아래에 "프로그램과 연결이 끊겼어요." 띠가 나온다. 새로 열린 화면을 쓴다.

3. 화면 보는 법

화면은 가운데 좁은 폭(앱 화면처럼)에 한 번에 한 가지만 보인다. 첫눈에 보이는 것은 큰 제목 한 줄, 짧은 설명 한 줄, 큰 버튼 하나다. 그래프·표·명세서 근거·AI가 한 일·반출 규칙 같은 자세한 내용은 지우지 않고 따로 떨어진 상세 페이지로 옮겼다. 목록의 줄이나 "›" 가 붙은 글을 누르면 같은 창에서 상세 페이지로 넘어가고(새 탭은 열리지 않는다), 맨 위 "← 돌아가기" 나 브라우저의 뒤로 가기로 앞 화면에 돌아온다. 화면마다 있는 작은 그림(말풍선, 문서와 돋보기, 달력, 파일 넣기 등)은 이해를 돕는 장식이고 정보는 글에 모두 있다.

화면에서는 "주문서"를 "받을 목록"(센터에서 내려받을 목록)이라고 부른다. 인쇄한 종이의 제목은 "센터 방문 주문서"다.

흐름은 질문 → (불러오는 중) → 받을 목록 → 받은 파일 이다. 머리 아래의 점 3개가 지금 몇 번째 단계인지 보여 준다(1 질문, 2 받을 목록, 3 받은 파일. 화면 읽기 프로그램에는 "3단계 중 1단계: 질문"처럼 읽힌다).

"프로그램 상태" 페이지 제목은 "프로그램이 준비됐어요" 이고, 그 아래에 "AI를 쓰고 있어요."(LLM 모드) 또는 "AI 없이 실행 중이에요."(규칙 모드)가 나온다. "자가 점검 9/9 통과", "실행 방식"(AI 사용 / AI 없이), "명세서", "공개 데이터"(카드·유동인구의 줄 수와 기간), "센터 파일 예시", AI 없이 실행할 때는 "원인"과 "할 일", 그리고 "점검한 것" 9줄이 이어진다. 점검에 실패한 줄이 있으면 제목이 "확인할 것이 있어요"가 된다.

질문 카드 위에는 필요할 때만 한 줄 안내가 하나 붙는다(먼저 해당하는 것 하나만).

  • 자가 점검에 확인할 것이 있으면 "프로그램 점검에서 확인할 것이 있어요."와 "보기 ›"(프로그램 상태로 간다).
  • 규칙 모드면 "지금은 AI 없이 실행 중이에요."(Key 는 있는데 AI 연결을 확인하지 못했으면 "AI 연결을 확인하지 못해 AI 없이 만들어요.")와 "직접 고르기가 더 정확해요 ›".

  • 받은 파일 결과가 있는 채로 오면 "새로 만들면 넣은 파일 결과는 화면에서 사라져요."

3.3 불러오는 중 화면

제목은 문장으로 물었으면 "질문을 읽고 있어요", 직접 골랐으면 "목록을 만들고 있어요". 설명 "받을 자료와 달을 찾는 중이에요.", 진행 막대, "n초 지났어요"가 보인다. 90초가 넘으면 "오래 걸리고 있어요. AI 응답이 없으면 AI 없이 만들어요."가 붙는다. 규칙 모드에서는 1~2초 만에 지나간다. 이 화면에서 뒤로 가도 만들기는 계속되고, 다 되면 머리 아래 띠가 알려 준다.

3.4 받을 목록 화면

제목 "이렇게 받으시면 돼요", 설명은 받는 횟수 한 줄이다(예: "센터에서 한 달 치씩 3번 받으면 돼요.", 자료가 둘이면 "자료 2가지를 한 달 치씩 6번 받으면 돼요.", 방법이 둘이면 "두 가지 방법 중 추천하는 방법이에요."). 그 아래에 줄 3개가 있고, 줄마다 "›" 를 누르면 상세 페이지가 열린다.

줄보이는 것누르면 열리는 상세 페이지
무엇을 받나요?받을 자료 이름(예: 카드 이용 현황(시간대)). 방법이 둘이면 "추천 방법" 표시자료 이름이 제목, "센터 화면에서 이 이름을 찾아 받으세요." 제공, 담긴 기간, 들어 있는 항목, 이 자료로 채우는 것, 받는 횟수, 알아 둘 점, 고른 까닭, "공개 데이터로 먼저 본 것 ›"

그 아래 버튼과 링크:

  • 큰 버튼 "목록 인쇄하기" (A4 한 장. 4절 3단계)
  • 보조 버튼 "받은 파일 넣기" (받은 파일 화면으로)

"이 결과를 믿어도 될까요?" 페이지

제목은 모두 맞으면 "명세서와 하나하나 맞춰 봤어요"(설명 "21개 항목이 모두 맞아요."), 센터 화면에서 확인할 줄이 있으면 "확인할 것이 있어요"(설명 "57개 가운데 55개는 같고, 2개는 센터 화면에서 확인해 주세요."). 아래 다섯 줄이 각각 상세 페이지로 이어진다. 맨 아래에 "화면의 숫자는 모두 프로그램이 계산한 값이에요."

줄상세 페이지에 있는 것
명세서와 맞춰 본 것 (예: 21/21 맞음)"센터 데이터 설명서(명세서)와 21개 항목을 모두 맞춰 봤어요." 받을 자료 이름, 달, 조건 값, 받을 항목, 받는 횟수를 설명서와 견준 결과. 확인할 줄이 있으면 그 조건과 까닭

상세 페이지의 "근거 원문"

상세 페이지 맨 아래에는 접힌 "근거 원문" 이 있다. 화면의 쉬운 말 대신 서버가 낸 원래 글이 그대로 들어 있다: 명세서 데이터 번호(예: 1-14), 조건의 컬럼 이름과 코드 값(예: biz_cd (업종코드) = I56111 (한식 음식점업)), 명세서 시트·컬럼 번호(예: "근거: 명세서 1-14 시트 6번 컬럼"), 받을 항목의 영문 컬럼 이름, 계절 지수 값, AI 사용 때는 모델 이름·주고받은 횟수·보낸 글과 받은 글의 토큰 수. 기본 화면에는 이런 번호와 코드를 내지 않는다. 인쇄본에는 들어간다.

목록의 낱말:

낱말뜻
받을 달센터에서는 한 번에 한 달 치만 내려받을 수 있다. 그래서 도 전체 공개 데이터의 1~12월 계절 지수에서 많은 달, 적은 달, 평균에 가까운 달 세 개를 골라 준다. 달마다 한 번씩, 세 번 받는다. "평소보다 10% 많음"은 계절 지수 110.0 을 뜻한다(지수 값은 "몇 월 치를 받나요?" 페이지의 막대와 인쇄본에 있다).
조건센터 화면에서 내려받을 때 걸 조건. 기본 화면에는 "노형동", "한식 음식점업"처럼 뜻만 보인다. 컬럼 이름과 코드 값은 "어떤 조건으로 받나요?" 페이지의 "근거 원문"과 인쇄본에 있다.
들어 있는 항목받은 파일에서 볼 컬럼. 영문 컬럼 이름은 "무엇을 받나요?" 페이지의 "근거 원문"과 인쇄본에 있다.
가져가기(반출)그 데이터를 센터 밖으로 가져갈 때의 기준(반출 정책에서 옮긴 줄). "이 결과를 믿어도 될까요?" › "가져가기(반출) 규칙"에 전부 있다.
21개 항목을 모두 맞춰 봤어요목록의 데이터 번호, 컬럼 이름, 조건 값, 받을 달, 필요한 단위를 명세서와 하나씩 대조해 모두 맞았다는 뜻이다. 어긋난 줄은 빼고 낸다(뺐으면 목록 위에 "설명서와 맞지 않는 줄이 있어 뺐어요."가 뜬다).
57개 가운데 55개는 같고, 2개는 센터 화면에서 확인해 주세요맞은 줄 가운데 그 데이터의 시트로는 표기를 확인하지 못한 줄이 있다는 뜻이다. 예: 포스 데이터(외식업 포스 고객 이용 현황)의 법정동명은 그 시트에 값 목록이 없어 카드 데이터의 법정동 목록을 빌려 대조한다. 그 조건에는 "센터 화면에서 이 이름이 맞는지 확인하세요"가 붙는다. 내려받기 화면에서 표기를 확인한다. 같은 줄이 견준 방법에도 들어 있으면 따로 세므로 확인할 것의 수가 보이는 줄 수보다 많을 수 있다.
센터에서 받아 채우는 것공개 데이터에 없는 정보를 목록의 센터 데이터로 메운다는 뜻이다("공개 데이터로 먼저 봤어요" 페이지의 "공개 데이터에 없는 것").
센터에도 없는 것명세서의 어느 데이터에도 그 정보가 없다는 뜻이다. 억지로 다른 데이터를 권하지 않고 "이 정보는 센터에 없어요"와 대신 볼 수 있는 것을 적는다.

"공개 데이터로 먼저 봤어요" 페이지

"무엇을 받나요?"나 "몇 월 치를 받나요?" 페이지 아래의 링크로 연다. 공개 데이터는 누구나 내려받을 수 있는 제주도 전체 통계다. 1~12월 계절 지수 막대, "달마다 어떻게 달라졌을까요?"(월별 이용금액 선 그래프, 2018년 1월~2025년 6월), 이용자구분별·성별 비중 표, 참고용 시간대별 방문인구 비중, 그리고 "공개 데이터에 없는 것"(센터에서 받아 채우는 것, 센터에도 없는 것)과 "공개 데이터로 볼 수 있는 것"이 있다. 그래프마다 "표로 보기"가 있다. 공개 데이터로 답할 수 없는 질문이면 "이 질문은 공개 데이터로는 볼 수 없어요."와 까닭이 나온다.

6.4 받을 목록(주문서)을 만들 때

보이는 것조치
"궁금한 것이 비어 있어요."한 문장으로 적거나 예시를 누른다.
"아무것도 고르지 않았어요.""직접 고르기"에서 누구·업종·언제·지역 가운데 하나 이상 고른다.
뜻과 다른 업종·지역으로 풀렸다받을 목록의 "무엇을 받나요?"와 "어떤 조건으로 받나요?", 그 상세 페이지의 "질문을 이렇게 읽었어요"를 본다. 제목 아래 "직접 고르기로 다시 만들기 ›"를 누르거나 질문 화면의 "직접 고르기 ›"에서 고른다.
줄 위에 노란 띠(예: "'함덕'은 명세서의 지역 이름이 아니라서 …")문장에서 지역 이름을 명세서에서 찾지 못해 도 전체로 풀었거나, 마을·해변 이름을 그것이 속한 읍면동으로 읽었거나, 업종을 42개 업종에서 찾지 못해 방문·유동인구로 푼 경우다. 띠의 "직접 고르기로 고치기 ›"를 눌러 그 칸에서 고른다.
"질문을 조금 바꿔 볼까요?"오류가 아니다. 버스·교통량·기업·와이파이·날씨·폐기물·메뉴처럼 주문서를 내는 범위 밖의 주제다. "센터에 있는 비슷한 자료 이름 보기 ›"에 명세서의 해당 데이터 이름만 나온다. 뜻과 다르게 읽혔으면 "질문 다시 하기"를 눌러 "직접 고르기"를 쓴다.
"센터에서 받을 것이 없어요"오류가 아니다. 필요한 정보가 모두 공개 데이터에 있다는 뜻이다(큰 버튼 "공개 데이터로 보기"를 누르면 공개 데이터 그래프 페이지가 열린다). 질문을 바꾸려면 "질문 다시 하기"를 누른다.
"이 정보는 센터에 없어요", 목록의 "연령대는 센터에도 없어요"오류가 아니다. 명세서의 어느 데이터에도 그 정보가 없다는 뜻이다. "대신 볼 것 보기"나 그 줄을 눌러 대신 볼 수 있는 것을 본다.
조건 줄의 "센터 화면에서 확인할 것이 있어요", "이 결과를 믿어도 될까요?"의 "확인할 것이 있어요"3.4절 낱말 표를 본다. 내려받기 화면에서 그 조건 값의 표기를 확인한다.
"설명서와 맞지 않는 줄이 있어 뺐어요."명세서와 어긋난 줄을 목록에서 뺐다는 뜻이다. "보기 ›"로 무엇을 뺐는지 본다.
명세서 대조 수나 받을 항목 수가 규칙 모드와 다르다(예: 21개가 아니라 17개나 30개)오류가 아니다. LLM 모드에서 AI 가 목적에서 필요한 단위를 다르게 읽으면 받을 항목과 대조하는 줄 수가 달라진다. 늘 같은 결과가 필요하면 "직접 고르기"에서 만든다.
시나리오 2 같은 문장에서 "다른 방법 보기"가 나오지 않는다LLM 모드에서는 실행마다 해석이 달라질 수 있다. 예시를 누른 뒤 "직접 고르기 ›"를 눌러 만든다(4절 6단계).
머리 아래 띠 "프로그램과 연결이 끊겼어요."검은 창이 닫혔다. run.bat(맥·리눅스는 run.sh)을 다시 실행한 뒤 띠의 "다시 연결"을 누른다. 주소의 숫자가 바뀌었으면 새로 열린 화면을 쓴다.
머리 아래 "보던 결과가 없어 처음 화면으로 왔어요."상세 페이지 주소를 새로 열었거나 결과를 지운 뒤 상세 페이지로 갔다. 질문부터 다시 한다.
"이 주소로는 프로그램을 쓸 수 없습니다."검은 창에 표시된 주소(http://127.0.0.1:숫자/)로 연다.

읽지 못한 파일은 받은 파일 화면 제목 바로 아래 빨간 상자에 파일마다 "파일", "원인", "할 일"이 나오고, 상자 끝에 "다른 파일 고르기"가 있다. 원인은 쉬운 말 한 줄로 나오고, 읽은 칸 이름 같은 자세한 원래 글은 그 상자의 "근거 원문"(접힘)에 있다. 읽었지만 주의할 점이 있는 파일은 결과 제목 아래 노란 띠(첫 문장과 "자세히 ›")로, 전체 점검 기록은 "자세히 보기" 페이지의 "근거 원문" › "파일 점검 기록"에 나온다. 아래 표의 왼쪽은 화면의 "원인"이나 띠의 첫머리다(2026-11-18 에 일부러 망가뜨린 파일을 넣어 옮긴 것. 표시가 없는 줄은 같은 방식으로 쉬운 말로 바뀌어 나온다).

"집계에 꼭 필요한 칸이 파일에 없어요."연월, 이용건수, 이용금액 칸이 빠졌다. 빠진 칸 이름은 "근거 원문"에 있다칸을 빼지 말고 다시 내려받는다.
"칸 이름 줄만 있고 데이터 줄이 없어요."조건이 너무 좁다조건을 넓혀 다시 내려받는다.

노란 띠 "한 파일에 여러 달(…)이 들어 있어요."달을 합친 파일표는 달을 합쳐 계산하고 공개 데이터와 견주지 않는다.

"공개 데이터와 견주기"에 차이(%)가 없음지역 조건을 걸어 받았거나 거래가 없는 법정동이 빠진 파일(법정동 73곳이 다 들어 있지 않음)정상이다. 차이(%)는 법정동이 모두 든 파일에서만 낸다.
"올린 파일을 임시 폴더(runtime)에 쓰지 못했…"프로그램 폴더에도 사용자 임시 폴더에도 쓸 수 없다폴더를 C:\center-order 처럼 바탕 화면·문서 폴더가 아닌 곳으로 옮겨 다시 실행한다.
노란 띠 "'월평동'… 이름이 같은 법정동이 두 곳 …"목록의 지역이 권역을 정하지 않은 월평동이다목록을 "제주시 월평동" 또는 "서귀포시 월평동"으로 다시 만든 뒤 넣는다.
"줄이나 열이 하나뿐인 교차표 n개는 내지 않았…" ("근거 원문"의 점검 기록)조건을 좁게 걸어 받아 교차표가 한 줄짜리 표와 같은 값이 된다정상이다. 가린 칸이 합계로 드러나지 않게 내지 않는다.
"파일이 너무 큽니다(2GB 까지)."달과 조건을 좁혀 다시 받는다.
노란 띠 "받을 목록과 다른 자료예요. 결과는 넣은 파일 기준이에요."목록에 없는 데이터의 파일을 넣었다결과는 넣은 파일 기준으로 나온다. 목록대로 받은 파일이 있으면 "파일 더 넣기"로 더 넣는다.

7.2 Key 설정

Key 는 화면에 입력하는 칸이 없다. 담당자가 미리 넣어 둔다. 방법은 둘이다.

방법하는 법비고
.env 파일프로그램 폴더에 .env 를 만들고 ANTHROPIC_API_KEY=값 한 줄을 넣는다(5.2절)간단하다. 파일이 프로그램 폴더에 그대로 있으므로 이용자가 열어 볼 수 있다.
Windows 환경변수"시스템 환경 변수 편집"에서 ANTHROPIC_API_KEY 를 추가한다환경변수가 .env 보다 먼저 적용된다. 프로그램 폴더에 Key 가 남지 않는다.
  • 프로그램은 Key 를 화면, 실행 창, 기록 파일에 출력하지 않는다.
  • 어느 방법이든 프로그램을 실행하는 Windows 계정은 그 값을 읽을 수 있다. 사용 한도를 건 센터 전용 Key 를 쓰는 것이 안전하다.
  • 모델은 MODEL 로 바꾼다. 비우면 claude-haiku-5-5 다.
  • 평가용으로 제출한 Key 는 평가 기간 뒤에 폐기된다. 운영할 때는 센터의 Key 로 바꿔 넣어야 한다.
  • Key 를 넣지 않으면 규칙 모드로 운영된다. 이때는 외부 접속이 없다.

7.3 외부 전송 범위

내용LLM(외부)으로 보내는가
이용자가 적은 목적 문장보낸다(LLM 모드에서 문장으로 적었을 때)
"직접 고르기" 선택값보내지 않는다(규칙으로 계산)
허브 공개 데이터의 집계값(계절 지수, 비중 등)보낸다. 공개 데이터에서 나온 값이다.
명세서의 데이터 이름·컬럼·수록 기간보낸다. 공개 자료다.
센터에서 내려받은 CSV 의 값, 그 집계 결과보내지 않는다. CSV 를 다시 계산하는 경로는 LLM 을 부르는 코드를 거치지 않는다.
파일 이름, 이용자 정보보내지 않는다. 계정이나 로그인이 없다.
  • 받을 목록의 "이 결과를 믿어도 될까요?" › "AI로 보낸 내용"에 실행마다 무엇을 몇 건 보냈는지 나온다. 그 줄의 "센터 값 0건"과 페이지의 "센터 파일 값 0건 · 다시 계산은 이 컴퓨터 안에서만 해요"는 언제나 0건이다. 받은 파일의 "자세히 보기"에도 "AI로 보낸 값 0건"이 붙고, 받은 파일 화면 아래에 "받은 파일은 센터 밖으로 가져갈 수 없어요."가 있다.
  • 주의: 이용자가 목적 문장 칸에 센터에서 본 수치를 직접 적으면 그 문장이 그대로 LLM 으로 나간다. 운영진은 이것도 외부 전송으로 본다고 답했다. 목적 문장에는 알고 싶은 것만 적고 센터 데이터의 값을 적지 않도록 안내한다.

7.4 보존하는 것과 결과 지우기("처음부터")

무엇어디언제 지워지나
올린 CSV 의 사본runtime\uploads"처음부터"를 눌러 지울 때. 읽지 못한 파일은 받은 즉시 지운다.
주문서 결과, CSV 를 다시 계산한 표(가린 뒤의 값)runtime\results"처음부터"를 눌러 지울 때
기록(언제 무엇을 했는지, 파일 이름, 줄 수, 검증 통과 수)runtime\logs\activity.jsonl"처음부터"를 눌러 지울 때
  • 계정, 이력 화면, 집계값을 쌓아 두는 기능은 없다. 프로그램이 스스로 꺼내 다시 쓰는 보존 자료는 없다.
  • 창을 닫는 것만으로는 runtime 폴더가 지워지지 않는다. 이용자가 바뀔 때마다 화면 오른쪽 위 "처음부터"를 눌러 지우도록 안내한다. 프로그램을 끈 뒤 runtime 폴더를 통째로 지워도 된다(다음 실행 때 다시 만들어진다). 지우지 않은 파일이 남아 있으면 다음 실행 때 질문 화면 위에 "지난번 결과가 남아 있어요."와 "지우기"가 뜬다.
  • 프로그램 폴더에 쓸 수 없어 사용자 임시 폴더(%TEMP%\center-order-runtime)를 쓰는 경우에도 "처음부터"가 그 폴더를 비운다. 어느 폴더를 쓰는지는 자가 점검의 "임시 폴더" 줄에 나온다.
  • "처음부터"는 화면 오른쪽 위에 늘 있다. 누르면 화면 안의 확인 카드 "처음부터 다시 할까요?"(지우기 / 취소)로 한 번 묻고, "지우기"를 누르면 지운 뒤 "지웠어요: 결과 n건, 넣은 파일 n개, 기록 n건."을 보이고 질문 화면으로 돌아간다.
  • "처음부터"는 이용자가 내려받은 원본 파일(바탕화면 등에 있는 것)은 건드리지 않는다.
  • 결과 지우기를 켜고 끄는 설정은 없다. 버튼은 항상 있다.

7.8 반출과의 관계

  • 다시 계산한 표는 비중·순위(응용집계)를 먼저, 건수·금액(단순집계)을 뒤에 보인다. 건수·금액·이용자수 가운데 하나라도 10 미만인 칸은 가리고("10 미만" 또는 "가림"), 합계·줄 합계·열 합계·총계도 10 미만이면 숨긴다. 한 표에서 가린 값이 같은 화면의 다른 표(교차표의 줄·열 합계, 비중 표)로 드러나지 않게 함께 가린다. 파일마다 "합계로 거꾸로 셈할 수 있는 칸 n개"를 화면에 적는다(0 이어야 한다).
  • 막는 범위: 합계에서 빼서 정확한 값이 나오는 경우다. "가린 두 칸의 합이 얼마 이하"처럼 범위를 좁혀 짐작하는 것, 값이 0 인 칸이 0 임을 아는 것까지는 막지 못한다.
  • 결과를 센터 밖으로 가져가려면 화면을 캡처한 그림으로 반출 신청을 한다. 프로그램은 파일을 만들어 주지 않는다.
  • 프로그램의 가리기는 반출 준비를 돕는 것이다. 반출 가부는 센터의 반출 심사가 정한다. 영리 목적 사용 가부도 프로그램이 판단하지 않는다.
