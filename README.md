# 센터 방문 주문서

**먼저 열 파일:** 이 문서와 사용자 매뉴얼은 더블클릭으로 읽을 수 있는 HTML 로도 들어 있다. `README.html`(이 문서), `docs/사용자_매뉴얼.html`(설치부터 5분 시연까지). 프로그램을 실행한 뒤에는 화면 바닥의 "도움말" › "사용 설명서 열기"를 눌러도 매뉴얼이 새 창에서 열린다.

제주빅데이터센터에서 내려받기 버튼을 누르기 전에, 무엇을 어느 달 치로 어떤 조건으로 받을지 한 장으로 정리해 주는 프로그램이다.

화면은 질문 → 받을 목록 → 받은 파일의 세 단계다. 데이터·컴퓨터에 익숙하지 않은 도민도 쓸 수 있게 가운데 좁은 폭에 한 화면 한 가지(큰 제목 한 줄, 짧은 설명 한 줄, 큰 버튼 하나)만 보이고, 그래프·표·명세서 근거·AI가 한 일·반출 규칙 같은 자세한 내용은 지우지 않고 따로 떨어진 상세 페이지로 옮겼다. 상세 페이지는 같은 창에서 주소(`#/…`)만 바뀌어 열리고, "← 돌아가기"와 브라우저의 뒤로 가기로 돌아온다. 화면에서는 주문서를 "받을 목록"(센터에서 내려받을 목록)이라고 부른다.

- **질문 "무엇이 궁금하세요?":** 알고 싶은 것을 평소 말로 한 문장 적거나, 예시 3개("노형동 한식당", "애월읍 카페", "성산읍 외국인 관광객")를 누르거나, "직접 고르기 ›"에서 누구·업종·언제·지역을 고른다. 큰 버튼은 "받을 목록 만들기". 누르면 "질문을 읽고 있어요"(진행 막대와 지난 초)가 잠깐 보인다.
- **받을 목록 "이렇게 받으시면 돼요":** 받는 횟수 한 줄(예: "센터에서 한 달 치씩 3번 받으면 돼요.")과 줄 3개("무엇을 받나요?", "몇 월 치를 받나요?", "어떤 조건으로 받나요?")만 보인다. 줄을 누르면 자료 설명, 받을 달을 고른 까닭(계절 지수 막대), 조건 설명 페이지가 열린다. 큰 버튼은 "목록 인쇄하기"(A4 한 장), 보조 버튼은 "받은 파일 넣기", 작은 링크 "이 결과를 믿어도 될까요?"에는 명세서 대조 수, AI가 한 일, AI로 보낸 내용(센터 값 0건), 반출 규칙, 알아 둘 점이 있다. 방법이 둘이면 "다른 방법 보기" 줄이, 메울 데이터가 없으면 "연령대는 센터에도 없어요" 같은 줄이 붙는다. 제주데이터허브 공개 데이터로 계산한 흐름은 "공개 데이터로 먼저 봤어요" 페이지에 있고, 명세서 번호·코드 값은 상세 페이지의 "근거 원문"과 인쇄본에 들어간다.
- **받은 파일 "받은 파일을 넣어 주세요":** 센터에서 내려받은 카드 이용 현황 v02 계열 CSV(명세서 1-08, 1-12, 1-14)를 끌어다 놓거나 "파일 고르기"로 넣으면 같은 분석을 그 파일로 다시 계산해 비어 있던 정보를 채운다. 결과는 한 문장(예: "저녁이 가장 많아요" / "2024년 8월, 18~22시가 카드 결제 건수의 42.1%예요.")과 막대 하나로 보이고, 다른 비중·숫자 표·가린 칸·공개 데이터와 견주기·점검 기록은 "자세히 보기" 페이지에 있다. 이 값은 LLM으로 보내지 않는다.

**주문서를 내는 범위:** 명세서 v13(2026-11-04) 기준 데이터 71종 가운데 카드·포스 소비 계열 22종과 방문·유동인구 계열 9종(31종)이다. 버스·교통량·기업·와이파이·날씨·폐기물·메뉴 등 나머지 40종의 주제는 주문서를 내지 않고, 짝짓지 못한다는 말과 함께 명세서의 해당 데이터 이름만 안내한다. 내려받은 CSV 로 다시 계산하는 것은 그 가운데 카드 v02 계열 3종이다.

"제주 AI·빅데이터 활용 AI Agent 개발 챌린지" 제출작이다.

## 1. 설치와 실행 3단계

설치하는 패키지는 없다. 파이썬 3.9 이상만 있으면 된다.

### Windows 11

참가자의 Windows PC 에서 제출 zip(이전 화면 판)을 풀어 `run.bat` 으로 실행해 정상 동작을 확인했다(2026-11-17). 3차 화면 판은 제출 전에 다시 확인할 예정이다.

| 단계 | 할 일 |
|---|---|
| 1 | 파이썬이 없으면 https://www.python.org/downloads/windows/ 에서 "Windows installer (64-bit)"를 받아 설치한다(시험한 판은 3.9.6 과 3.14.5 다. 새로 설치한다면 3.14.x 를 권한다). 설치 첫 화면 아래쪽의 **"Add python.exe to PATH"** 를 체크한 뒤 "Install Now"를 누른다. 이미 파이썬 3.9 이상이 있으면 건너뛴다. |
| 2 | 제출 zip 을 **압축 풀기**로 푼다(zip 안에서 바로 실행하지 않는다). 풀린 폴더는 `C:\center-order` 처럼 내 PC 안의 폴더에 둔다. |
| 3 | 폴더 안의 **`run.bat`** 을 더블클릭한다. 검은 창이 열리고 자가 점검 결과가 나온 뒤 브라우저(Chrome 또는 Edge)에 화면이 열린다. |

- 끝낼 때는 화면 오른쪽 위 "처음부터"(결과 지우기)를 눌러 지운 뒤 검은 창을 닫는다.
- 브라우저가 열리지 않으면 검은 창에 표시된 `http://127.0.0.1:숫자/` 주소를 브라우저 주소창에 붙여 넣는다. 숫자(포트)는 실행할 때마다 빈 번호로 바뀐다.
- 보안 경고가 뜰 때의 조치는 `docs/사용자_매뉴얼.md` 2절에 있다.

### macOS, Linux

| 단계 | 할 일 |
|---|---|
| 1 | 파이썬 3.9 이상이 있는지 확인한다: 터미널에서 `python3 --version` |
| 2 | zip 을 풀고 터미널에서 그 폴더로 간다. |
| 3 | `sh run.sh` 를 실행한다. 브라우저가 열린다. 끝낼 때는 터미널에서 Ctrl+C 를 누른다. |

### 실행 옵션(쓰지 않아도 된다)

`run.bat` 과 `run.sh` 뒤에 붙인다.

| 옵션 | 뜻 |
|---|---|
| `--port 번호` | 포트를 정한다. 주지 않으면 빈 포트를 고른다. |
| `--no-browser` | 브라우저를 자동으로 열지 않는다. |
| `--runtime 폴더` | 올린 파일·결과·기록을 둘 폴더를 정한다. 기본은 프로그램 폴더 아래 `runtime`. |
| `--verbose` | 요청마다 실행 창에 한 줄씩 쓴다. 주지 않으면 시작할 때의 글과 오류만 쓴다. |

## 2. 의존성

| 항목 | 내용 |
|---|---|
| 파이썬 | 3.9 이상. 개발 기기(macOS)에서 3.14.5 와 3.9.6 으로 시험했다. 3.15 이상과 "Python install manager"로 설치한 파이썬에서는 돌려 보지 못했다. |
| 파이썬 패키지 | **없음.** 표준 라이브러리만 쓴다. `pip install` 을 하지 않는다. |
| 브라우저 | Chrome 또는 Edge. 화면은 HTML·CSS·JS·SVG 로만 그리며 바깥에서 불러오는 글꼴·그림·스크립트가 없다. |
| 인터넷 | 규칙 모드에서는 필요 없다. LLM 모드에서만 `api.anthropic.com` 에 접속한다. |

패키지를 쓰지 않은 이유: 운영진이 "서명이 없는 오픈소스 패키지 및 확장 모듈은 센터 PC의 보안정책에 따라 실행이 제한된다"고 답했다(대회 게시판). 그래서 LLM 호출도 SDK 없이 표준 라이브러리(`urllib`)로 한다.

## 3. 환경변수와 Key 넣는 법

Key 가 없어도 프로그램은 **규칙 모드**로 끝까지 돈다. Key 를 넣으면 **LLM 모드**가 켜진다.

| 이름 | 뜻 | 비우면 |
|---|---|---|
| `ANTHROPIC_API_KEY` | Claude API Key | 규칙 모드로 실행 |
| `MODEL` | 쓸 모델 ID | `claude-haiku-5-5` |
| `API_BASE` | API 주소 | `https://api.anthropic.com` |
| `EFFORT` | 선택. `low`, `medium`, `high`, `xhigh`, `max` 가운데 하나 | 보내지 않음(모델 기본값) |

### `.env` 파일

- **위치:** 프로그램 폴더 바로 아래(`run.bat` 과 같은 자리)의 `.env`.
- **형식:** 한 줄에 `이름=값`. `#` 으로 시작하는 줄은 주석이다. 값에 따옴표를 둘러도 된다. 인코딩은 UTF-8 을 권한다. UTF-16(PowerShell 로 만든 파일)과 CP949(메모장의 ANSI 저장)도 읽는다. 읽지 못하면 화면에 "Key 없음"이 아니라 ".env 파일을 읽지 못했다"고 나온다.
- **만드는 법:** 같은 폴더의 `.env.example` 을 복사해 이름을 `.env` 로 바꾸고, `ANTHROPIC_API_KEY=` 뒤에 Key 를 붙여 넣는다.
- **적용:** 저장한 뒤 프로그램을 다시 실행한다(검은 창을 닫고 `run.bat` 을 다시 더블클릭).
- **우선순위:** 운영체제 환경변수에 같은 이름이 있으면 환경변수가 `.env` 보다 먼저다.
- 프로그램 폴더에 `.env` 가 이미 들어 있으면(평가용 제출본) 따로 할 일이 없다.

예시(값은 직접 넣는다. 이 문서와 `.env.example` 에는 실제 Key 가 없다):

```text
ANTHROPIC_API_KEY=
MODEL=
API_BASE=
```

Key 는 요청 헤더에만 들어가며 화면, 실행 창, 기록 파일에 출력하지 않는다. 화면 바닥의 "프로그램 상태" 페이지에 "AI를 쓰고 있어요."(LLM 모드) 또는 "AI 없이 실행 중이에요."(규칙 모드)가 나오고, 규칙 모드라면 같은 페이지에 "원인"과 "할 일"이 있다. 규칙 모드에서는 질문 화면 위에도 "지금은 AI 없이 실행 중이에요."가 뜬다.

평가용 Key 는 평가 기간 뒤에 폐기한다. 센터에 탑재할 때는 센터 담당자가 센터의 Key 로 바꿔 넣는다(`docs/사용자_매뉴얼.md` 7절).

## 4. 폴더 구성

```text
run.bat              Windows 실행 파일
run.sh               macOS·Linux 실행 파일
README.md            이 문서
.env.example         환경변수 예시(값 없음)
app/                 프로그램 본체
  server.py            로컬 서버(127.0.0.1), 화면과 API 5개
  agent.py             Agent 루프(Claude API 호출, 도구 5개, 검증기 되돌림, 규칙 모드로 넘기기)
  planner.py           규칙 계획기, 도구 5개의 실제 계산, 주문서 조립
  validator.py         검증기(주문서를 명세서와 대조)
  catalog.py           명세 카탈로그(spec.json) 읽기
  public_data.py       허브 1048·520 적재, 월별 집계, 계절 지수, 비중
  center_csv.py        내려받은 CSV 인식과 재분석(LLM 호출 없음)
  masking.py           10 미만 가리기와 역산 방지
  selfcheck.py         자가 점검
  config.py            경로와 고정 값(내려받기 상한, 가리기 기준 등)
  prompts/system.md    시스템 프롬프트
  prompts/tools.json   도구 5개의 정의(입력 형식)
  INTERFACES.md        모듈 사이의 함수 사용법(개발자용)
web/                 화면(index.html, app.js, style.css), manual.html(화면의 "도움말" › "사용 설명서 열기"가 여는 매뉴얼)
data/
  public/              허브 공개 데이터 실물 CSV 2종(1048, 520)
  spec/                데이터명세서_kr.xlsx(v13), spec.json, dim_tags.json, hub_center_map.json, aliases.json
  sample_center/       가상 센터 CSV 3종, manifest.json, 가상데이터_설명.md
tools/
  build_spec.py            명세서 xlsx → spec.json
  make_sample_center.py    가상 센터 CSV 생성(고정 시드 20261117)
  make_placeholder_public.py  허브 실물이 없을 때만 쓰는 대체 파일 생성
  e2e.py                   처음부터 끝까지 재현(시나리오 3개, CSV 재분석, 삭제)
  make_docs_html.py        문서 .md → .html(더블클릭으로 읽는 판)
  make_zip.py              제출 zip 묶기와 확인(한글 이름, 빼야 할 파일)
tests/               단위 시험(unittest)과 모의 LLM 서버
docs/                사용자 매뉴얼, 데이터 활용 명세, 결과 설명자료(.md 와 .html), 실호출 기록
README.html          이 문서의 HTML 판
```

실행하면 프로그램 폴더 아래에 `runtime/` 이 생긴다. 올린 파일, 만든 결과, 기록은 여기에만 쓰고, 화면의 "처음부터" 버튼이 모두 지운다. 프로그램 폴더에 쓸 수 없으면(읽기 전용 위치, 보안 프로그램의 폴더 보호) 운영체제의 사용자 임시 폴더 아래 `center-order-runtime` 을 대신 쓰고, 자가 점검의 "임시 폴더" 줄에 그 경로를 적는다.

## 5. 사용 모델과 라이브러리

| 항목 | 내용 |
|---|---|
| LLM | Anthropic Claude. 기본 모델 ID `claude-haiku-5-5`(Claude 의 저가 등급인 Haiku 계열로, 운영 비용을 고려해 골랐다). `.env` 의 `MODEL` 로 바꿀 수 있다. |
| 호출 방식 | Claude Messages API(`POST /v1/messages`)를 `urllib` 로 직접 호출. 헤더 `anthropic-version: 2026-10-21`. 도구 호출(tool use) 루프. 시스템 프롬프트는 프롬프트 캐시 대상으로 표시한다. |
| SDK | 쓰지 않는다(anthropic SDK 포함). |
| 파이썬 라이브러리 | 표준 라이브러리만: `http.server`, `urllib`, `ssl`, `json`, `csv`, `zipfile`, `xml.etree`, `hashlib`, `threading`, `unittest` 등. |
| 화면 | 순수 HTML·CSS·JS·SVG. 프레임워크와 외부 자원 없음. |
| 로컬 LLM | 쓰지 않는다. |

## 6. AI 활용 범위

### 프로그램 안에서 LLM 이 하는 일

| LLM 이 한다(LLM 모드) | LLM 이 하지 않는다(코드가 한다) |
|---|---|
| 목적 문장을 읽어 지역·업종·대상·필요한 단위를 정한다 | 모든 수치 계산(월별 집계, 계절 지수, 비중, 재분석 표) |
| 도구 5개를 어떤 순서로 부를지 정한다 | 명세서에서 후보 데이터 찾기와 버린 이유 대기 |
| 한 데이터로 안 될 때 두 안 가운데 무엇을 먼저 권할지 고른다 | 받을 달 3개 고르기, 조건 값과 쓸 컬럼 채우기 |
| 데이터를 고른 이유를 글로 쓴다 | 검증(데이터 번호·컬럼·조건 값·달을 명세서와 대조), 10 미만 가리기 |

- LLM 이 쓴 글에서 숫자가 든 문장과 수량·순위를 말하는 한글 표현("절반", "두 배", "일등" 등)이 든 문장은 코드가 빼고 화면에 내지 않는다. LLM 이 도구 인자에 적은 글자도 검사를 통과한 것만 기록에 옮긴다. 화면의 숫자는 전부 코드가 계산한 값이다. 숫자도 수량 낱말도 없이 쓴 서술까지는 걸러 내지 못한다.
- 문장에 요일·시간대를 가리키는 말이 없는데 LLM 이 그 단위를 넣으면 코드가 뺀다(받을 데이터가 늘지 않게).
- 버스·날씨처럼 범위 밖 주제로 읽힌 문장은 LLM 을 부르지 않고 코드가 "짝짓지 못한다"고 답한다.
- LLM 이 낸 주문서 초안은 검증기를 거친다. 어긋나면 어긋난 줄을 되돌려 보내 고치게 하고(최대 2회), 그래도 어긋나면 주문 항목을 코드가 규칙으로 다시 짠다.
- **내려받은 센터 CSV 를 다시 계산하는 단계에는 LLM 호출이 없다.** 센터 CSV 의 값은 이 PC 밖으로 나가지 않는다.
- LLM 을 쓰지 못하면(Key 없음, 연결 실패, 한도 초과, 시간 초과 등) 규칙 모드로 넘기고 화면에 이유를 적는다. 규칙 모드에서는 문장을 프로그램에 든 낱말 사전으로 풀고, 두 안 가운데 먼저 권할 안을 정해진 규칙으로 고른다.

### 개발 과정

코드와 문서를 만드는 데 생성형 AI 도구(Anthropic Claude Code)를 썼다. 프로그램의 동작과 문서의 수치는 8절의 검증 명령으로 다시 확인할 수 있다.

python3 tools/build_spec.py --check      명세서를 다시 변환해 spec.json 과 같은지 확인

## 9. 오류와 제약사항

### 확인하지 못한 것

| 항목 | 상태 |
|---|---|
| Windows 에서 `run.bat` 실행 | **참가자 Windows PC 에서 실행 확인(2026-11-17, 이전 화면 판).** 제출 zip 을 풀어 `run.bat` 으로 실행해 화면이 정상으로 뜨고 동작하는 것을 확인했다. **3차 화면 판(2026-11-18 저녁에 한 화면 한 가지로 다시 만들고 자세한 것은 상세 페이지로 옮긴 화면)은 제출 전 다시 확인 예정이다.** 그 밖에 Windows 에서 생길 수 있는 일(쓰기 금지 폴더, 끊긴 연결, CP949 출력, UTF-16·CP949 `.env`, zip 안에서 실행, 기관 망 인증서)은 코드와 시험으로 대비했다. |
| 센터 PC 에서의 실행 | **확인 못 함.** 센터 PC 의 보안정책이 파이썬 공식 설치판과 배치 파일 실행을 허용하는지 모른다. |
| 제출 zip 의 한글 파일 이름 | 이전 화면 판 zip 을 참가자 Windows PC 에서 풀어 실행까지 했다. 한글 문서 이름의 표시는 따로 기록하지 않았다. `tools/make_zip.py` 가 이름을 NFC 로 맞춰 UTF-8 표시와 함께 넣고 다시 열어 확인한다. |
| 실제 센터 망에서의 LLM 호출 | **확인 못 함.** macOS 개발 기기에서는 실제 Claude API 로 시나리오 3개가 LLM 모드로 끝까지 돌았다(8절). 센터 망의 차단·인증서 환경에서는 돌려 보지 못했다. 실패하면 규칙 모드로 넘어가 화면에 이유와 조치가 나온다. |
| 실제 센터 CSV | **본 적 없음.** 동봉한 센터 CSV 는 명세서대로 만든 가상 파일이다. 형식은 운영진이 게시판에 공개한 규칙과 예시 줄로 시험했다. |

### 기능 범위

- 주문서를 내는 범위는 카드·포스 소비 계열 22종과 방문·유동인구 계열 9종이다. 나머지 40종의 주제(버스, 교통량, 기업, 와이파이, 날씨, 폐기물, 메뉴 등)는 주문서를 내지 않고 데이터 이름만 안내한다. 주제는 문장에 든 낱말로 가리므로, 낱말 사전에 없는 범위 밖 주제는 두 계열 가운데 하나로 풀릴 수 있다.
- 다시 계산(재분석)은 카드 이용 현황 v02 계열 3종(1-08, 1-12, 1-14)만 된다. 다른 데이터의 CSV 를 넣으면 어떤 데이터인지와 줄 수만 알려 준다.
- 지역은 명세서의 법정동·행정동·권역·시 이름만 조건으로 쓴다. 마을(리)·해변·명소 이름은 자주 쓰는 18개만 그것이 속한 읍면동으로 읽고(주문서 위에 그렇게 읽었다고 경고한다), 그 밖의 이름은 찾지 못했다고 경고한 뒤 도 전체로 푼다.
- 가리기는 합계에서 빼서 정확한 값이 나오는 길을 막는다(합계 칸과 표 사이의 역산 포함). 범위를 좁혀 짐작하는 것과 0 인 칸이 0 임을 아는 것까지는 막지 못한다.
- 입력은 문장 한 번 또는 "직접 고르기" 선택이다. 이어 묻는 대화는 없다.
- 받을 달은 도 전체 공개 데이터의 계절 지수로 고른다. 읍면동에서는 많은 달과 적은 달이 다를 수 있다.
- 명세서의 "현재까지" 데이터는 실제 최신 달이 명세서에 없다. 공개 데이터와 겹치는 달이 없는 데이터는 오늘 기준 3개월 앞선 달까지 있다고 가정하고 주문서에 그렇게 적는다. 그래서 그런 주문서의 받을 달은 실행하는 날짜에 따라 달라진다.
- 규칙 모드의 문장 해석은 낱말 사전(`data/spec/aliases.json`)에 든 말만 알아듣는다. 뜻대로 풀리지 않으면 "직접 고르기"를 쓴다. 소비를 묻는 문장인데 업종을 42개 업종에서 찾지 못하면 방문·유동인구로 풀고 받을 목록 위 노란 띠에 그렇게 풀었다고 경고한다("직접 고르기로 고치기 ›").
- 직접 고르기에는 "20대", "토요일" 같은 특정 값을 넣는 칸이 없다. 그런 값은 문장으로 적어야 반영된다.
- LLM 모드에서 시나리오 2(애월읍 카페, 요일과 시간대를 함께) 같은 문장은 실행마다 해석이 달라 두 방법("다른 방법 보기")이 나오지 않을 수 있다. 시연은 예시를 누른 뒤 "직접 고르기"로 만드는 것을 권한다(규칙으로 계산해 늘 같은 결과가 나온다).
- LLM 모드에서 받을 항목은 코드가 목적에서 정한 목록이 기준이고 AI 는 항목을 더하기만 한다(빼지 못한다). 다만 AI 가 목적에서 필요한 단위를 실행마다 다르게 읽을 수 있어, 받을 항목 수와 명세서 대조 항목 수가 달라질 수 있다(시나리오 1 실호출에서 대조 17개~30개, 모두 통과. 2026-11-18 화면 확인 때 시나리오 1 문장의 받을 항목이 한 번은 7가지, 한 번은 6가지였다). 같은 결과가 필요하면 "직접 고르기"로 만든다(규칙으로 계산해 늘 21/21).
- 검증의 "확인 못 함": 포스 데이터(1-19, 1-22, 1-24)의 법정동명은 그 시트에 값 목록이 없어 카드 1-07 의 법정동 목록을 빌려 대조한다. 이런 줄은 따로 세어 받을 목록의 조건 줄에 "센터 화면에서 확인할 것이 있어요", "이 결과를 믿어도 될까요?" 페이지에 "57개 가운데 55개는 같고, 2개는 센터 화면에서 확인해 주세요."처럼 보이고, 조건 페이지의 그 조건에 "센터 화면에서 이 이름이 맞는지 확인하세요"가 붙는다.
- 받을 목록 기본 화면(제목, 줄 3개, "목록 인쇄하기", "받은 파일 넣기", "이 결과를 믿어도 될까요?")은 시나리오 3개 모두 1920×1080 의 첫 화면 안에 들어온다. 1366×768 에서는 규칙 모드 시나리오 3개 모두 "목록 인쇄하기"까지 첫 화면 안이고 "받은 파일 넣기"와 "이 결과를 믿어도 될까요?"는 조금 내려야 보인다(2026-11-18 문서 담당 측정, 가로 스크롤 없음). 상세 페이지 가운데 받은 파일의 "자세히 보기"는 막대 묶음이 3~4개라 길다. 인쇄는 A4 한 쪽에 맞춘다(구현 담당이 브라우저의 PDF 인쇄로 1쪽 확인. 실제 프린터 출력은 보지 않았다).
- 컬럼 이름이 서로 같은 데이터 4쌍(1-02·1-05, 1-03·1-06, 2-01·2-02, 5-05·5-06)의 CSV 를 넣으면 화면은 후보 목록만 보여 준다. 화면에서 하나를 골라 다시 보내는 기능은 없다(네 쌍 모두 재분석 대상이 아니다).
- 그림·PDF·한글 보고서 파일을 만들지 않는다. 주문서는 "목록 인쇄하기" 버튼으로 인쇄하고, 재분석 결과는 화면 캡처로 반출 신청을 한다.
- 올린 파일 한 개의 크기는 2GB 까지다.

### 보존과 삭제

- 올린 CSV 의 사본, 만든 결과, 기록은 프로그램 폴더의 `runtime/` 에 남는다. **창을 닫는 것만으로는 지워지지 않는다.** 이용을 마치면 화면 오른쪽 위의 "처음부터" 버튼을 누른다(화면 안 확인 카드로 한 번 묻고 지운다). 지우지 않고 끝냈으면 다음 실행 때 질문 화면 위에 "지난번 결과가 남아 있어요."와 "지우기"가 뜬다.
- 기록 파일에는 언제 무엇을 했는지(주문서 만들기, 파일 이름, 줄 수, 검증 통과 수)만 남고 CSV 의 값은 남지 않는다.

### 자주 나는 오류
