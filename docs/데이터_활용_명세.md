# 데이터 활용 명세

센터 방문 주문서가 쓰는 데이터의 출처, 이용조건, 쓴 컬럼, 전처리, 분석 흐름, 한계를 적는다. 이 문서의 행 수·기간·종수는 2026-11-17 에 동봉한 파일을 프로그램과 스크립트로 직접 세어 확인한 값이다.

- 허브 공개 데이터 2종은 **실물 파일**이다. 대체 파일이나 표본이 아니다. 화면 오른쪽 위에 "공개 데이터: 대체 파일로 계산 중"이 뜨지 않고, "프로그램 상태"를 눌렀을 때 공개 데이터 줄에 실물 파일 이름(업종별성별카드이용정보.csv, 제주도방문내국인유동인구추이.csv)이 나오면 실물로 계산하고 있는 것이다.
- 센터 방문 데이터(비공개)는 쓰지 않았다. 센터를 방문하지 않아 실제 센터 CSV 는 한 번도 보지 못했다.
- 대회 페이지가 제공한 xlsx 2종("제주데이터허브 데이터목록", "예시데이터 및 컬럼확인용")은 쓰지 않았고 폴더에 넣지 않았다.

### 2.3 이용조건

| 항목 | 내용 |
|---|---|
| 허브 페이지의 이용조건 표기 | 두 데이터의 상세 페이지에 이용조건·공공누리 유형 표기가 없다(2026-11-17 확인). |
| 운영진 답변(대회 게시판 43번) | 허브에서 제공되는 공개 데이터는 제출 zip 에 넣을 수 있다. 「공공데이터의 제공 및 이용 활성화에 관한 법률」과 시행령에 맞춰 활용한다. 출처와 전처리·적재 방식을 데이터 활용 명세에 적는다. |
| 운영진 답변(대회 게시판 39번) | 제출물을 센터 밖에 공개할 때는 허브 원문 자료를 함께 넣어 배포하지 말고 출처와 원문 링크를 적어 직접 내려받게 안내한다. |
| 이 제출물의 처리 | 원본 CSV 를 고치지 않고 제출 zip 에만 넣었다. GitHub 등 외부 저장소에 올리지 않았다. 화면에 출처(허브 번호와 데이터명, 기간)를 표시한다(2단계 "공개 데이터로 먼저 본 흐름"의 "출처와 계산 방법"). |
| 센터 밖에 배포할 경우 | `data/public/` 을 비우고 "제주데이터허브 1048, 520 상세 페이지에서 첨부 CSV 를 받아 `data/public/` 에 넣는다"로 안내하면 된다. 프로그램은 파일 이름이 아니라 첫 줄(컬럼 이름)로 두 파일을 알아본다. |

| 항목 | 내용 |

| 출처 | 제주데이터허브 > 제주빅데이터센터 > 제공데이터 화면 https://jejudatahub.net/center/data (로그인 없이 받을 수 있는 공개 자료) |
| 취득일 | 2026-11-17 |

| 동봉 파일 | `data/spec/데이터명세서_kr.xlsx`, 3,174,101바이트, 받은 그대로. SHA-256 앞 16자리 `f8d95532b05462c4` |

프로그램이 센 값(`python3 tools/build_spec.py --check` 출력):

| 항목 | 값 |
|---|---|
| 표기 | 명세서 v13(2026-11-04) 기준 데이터 71종, 참고표 2종 |
| 시트 | 74개 |
| 컬럼 | 906개(파티션 컬럼 136개 포함) |
| 카테고리별 | 경제 32, 기업 8, 교통 10, 통신 15, 환경 6 |
| 반출 표기 | 가능 22, 불가능 49 |
| 수록 기간을 달 범위로 판정할 수 있는 데이터 | 48종 |
| 컬럼 이름이 서로 같은 묶음 | 4개(1-02·1-05, 1-03·1-06, 2-01·2-02, 5-05·5-06) |
| 목록 시트와 데이터 시트가 다른 곳 | 7건(유동인구 6종의 제공처, 5-06 의 이름) |

명세서에서 읽어 쓰는 항목: 데이터 번호와 이름, 카테고리, 반출 가부와 문구, 제공처, 수록 기간, 설명, 컬럼(번호·영문명·한글명·형식·예시·비고), 시트 안의 참고표(법정동, 업종코드, 시간대, 연령대 등), 참고표 시트.

변환할 때 흡수한 것:

| 명세서의 모양 | 처리 |
|---|---|
| 목록 시트와 데이터 시트의 제공처가 다른 곳이 있다 | 각 데이터 시트의 값을 쓴다. |
| 예시값에 틀린 조합이 있다(예: 업종코드와 업종명이 어긋남) | 예시값이 아니라 참고표를 기준으로 삼는다. |
| 머리글 표기가 두 가지이고 한 시트는 한 행 밀려 있다 | 둘 다 읽는다. |
| 기간 표기가 여러 가지다("~ 현재까지", 구간 두 개, 시점 한 번 등) | 달 범위로 바꿀 수 있는 것만 범위로 쓰고, 못 바꾸는 것은 주문서에 "수록 기간이 명세서에 없음"으로 적는다. |
| 컬럼명 뒤에 공백이 붙은 곳이 있다 | 지우고 읽는다. |
| 파티션 컬럼(pt_year, pt_month) | 표시만 하고 "쓸 컬럼"과 조건에서 뺀다. |
| 메뉴코드표(4,889행) | 값은 싣지 않고 행 수만 적는다(메뉴 단위 분석은 범위 밖). |

## 8. 분석 흐름

```text
목적(1단계: 문장으로 적기 또는 직접 고르기)
  → 필요한 단위 결정(지역·업종·대상·요일·시간대·연령대 등)
  → 공개 데이터 계산(허브 1048 또는 520): 월별 추이, 1~12월 계절 지수, 비중
  → 빈칸 표시: 필요한 단위 가운데 공개 데이터에 없는 것
  → 명세서 짝짓기: 빈칸 단위를 가진 센터 데이터를 컬럼 수준에서 찾기, 안 되면 두 안 비교, 없으면 "메울 데이터 없음"
  → 받을 달 3개: 계절 지수의 많은 달·적은 달·평균에 가까운 달, 연도는 센터 데이터의 수록 범위 안에서
  → 검증기: 데이터 번호·컬럼·조건 값·달을 명세서와 대조
  → 주문서 한 장(2단계 화면, 인쇄)
  → (센터에서 내려받은 뒤) 3단계에 CSV 넣기 → 헤더로 인식 → 같은 분석을 그 파일로 다시 계산 → 10 미만 가리기 → 허브 값과 대조 줄
```

### 8.1 공개 데이터 계산 방법

| 계산 | 방법 |
|---|---|
| 월별 추이 | 목적의 업종(1048) 또는 대상(520)으로 거른 뒤 월마다 더한다. 1048 의 기본 지표는 이용금액이다. |
| 1~12월 계절 지수 | 12달이 다 있는 해마다 "그 달 값 ÷ 그 해 월평균"을 구하고, 달마다 여러 해의 평균을 낸다(평균 = 100). 1048 은 2018~2024 일곱 해, 520 은 2022-07 이후 구간에서 12달이 다 있는 2023·2024 두 해를 쓴다. |
| 많은 달·적은 달·평균에 가까운 달 | 계절 지수가 가장 큰 달, 가장 작은 달, 나머지 가운데 100 에 가장 가까운 달 |
| 비중 | 최근 12개월의 이용자구분별·성별(1048), 시간대별·연령대별·성별(520) 비중 |
| 받을 달의 연도 | (1) 센터 데이터의 수록 범위와 공개 데이터 기간이 겹치면 그 범위에서 가장 최근 해(공개 값과 대조할 수 있다). (2) 겹치는 달이 없으면 수록 범위 안에서 가장 최근 해. 끝이 "현재까지"면 오늘 기준 3개월 앞선 달까지 있다고 가정하고 주문서에 그렇게 적는다. |

예: 시나리오 1(노형동 한식당)의 한식 음식점업 계절 지수는 8월 110.0(많은 달), 2월 87.7(적은 달), 4월 100.7(평균에 가까운 달)이고, 1-14(2023-08 ~ 현재까지)와 1048(~2025-06)이 겹치는 범위에서 가장 최근 해로 맞춰 받을 달이 2024-08, 2025-02, 2025-04 가 된다.

### 8.2 재분석(내려받은 CSV)

| 항목 | 내용 |
|---|---|
| 대상 | 카드 이용 현황 v02 계열 3종: 1-08(읍면동), 1-12(요일별), 1-14(시간대) |
| 범위 | 주문서의 지역(법정동)과 업종으로 거른다. 주문서가 없으면 파일 전체로 계산한다. |
| 응용집계(먼저 보임) | 시간대별 또는 요일별 비중과 순위, 이용자구분별·연령대별 비중, 법정동별 비중과 순위(상위 10곳과 요청한 곳) |
| 단순집계(뒤에 보임) | 시간대(요일)별 이용건수·이용금액, 시간대(요일) × 이용자구분, 시간대(요일) × 연령대 이용건수 |
| 가리기 | 가리는 기준 값은 그 칸의 이용건수 합·이용금액 합·이용자수 합(0 이면 뺌) 가운데 가장 작은 값이다(최종 표시값 기준. 금액에도 적용). 10 미만이면 가린다: 보일 값이 10 미만이면 "10 미만", 값은 10 이상인데 이용자수 때문에 가리면 "가림". 한 줄이나 한 열에 가린 칸이 하나뿐이면 합계에서 빼서 알 수 있으므로 다음으로 작은 칸도 "가림"으로 가린다. 합계·줄 합계·열 합계·총계도 10 미만이면 "숨김"으로 바꾼다. 비중 표도 같은 결정으로 가린다. |
| 표 사이의 역산 | 한 화면의 표가 같은 값을 나눠 보이므로(시간대별 표의 값 = 교차표의 줄 합계), 한 줄짜리 표에서 가린 값은 교차표의 줄·열 합계에서도 숨기고 그 줄(열)의 칸 하나를 함께 가린다. 줄이나 열이 하나뿐인 교차표는 내지 않는다. 법정동별 비중 표는 파일에 든 법정동이 모두 나올 때 가린 곳이 하나뿐이면 다음으로 작은 곳도 가린다. 화면 전체의 "합 = 부분의 합" 관계를 점검해 거꾸로 셈할 수 있는 값의 수를 파일마다 적는다(동봉 가상 3종에서 0). 범위를 좁혀 짐작하는 것과 0 인 칸은 막지 못한다. |
| 대조 줄 | 파일의 그 달·그 업종 이용금액 합계와 허브 1048 의 도 전체 값의 차이(%). "검증"이 아니라 "차이"로 적는다(9절). 차이는 파일에 법정동 73곳이 모두 들어 있을 때만 낸다. 지역 조건을 걸어 받았거나 법정동이 빠진 파일은 "도 전체 값과 견주지 않았다"고만 적는다. 동봉 가상 파일이면 "차이 0.0% 는 만든 방식 때문"이라는 말을 맨 앞에 적는다. |
| 결측(NA) | 연령대가 NA 인 줄은 "NA(알 수 없음)" 한 줄로 모으고 순위에서 뺀다(명세서 1-14 의 연령대 값 목록에 NA 가 있다). |
| 외부 전송 | 없음. 이 단계는 LLM 을 부르지 않고 네트워크를 쓰지 않는다. |

## 9. 허브·센터 컬럼 대응표

`data/spec/hub_center_map.json` 의 내용이다. 관계는 **"같은 원천의 도 전체 집계본으로 보임(추정)"** 이다.

### 9.1 허브 1048 ↔ 센터 카드 이용 현황(1-07, 1-08, 1-11, 1-12, 1-13, 1-14)

| 허브 1048 (파일 컬럼 / 화면 이름) | 센터 컬럼 | 대응 |
|---|---|---|
| `base_year_month` / 연월 | `base_year_month` | 표기가 같다(YYYYMM). |
| `biz_nm` / 업종명 | `biz_nm` | 센터 참고표의 42개 업종명과 같다(쉼표 한 곳, 깨진 글자 한 달을 빼면 글자까지 같음). 1048 에는 업종코드가 없어 조건에 쓸 코드(`biz_cd`)는 센터 참고표에서 찾는다. |
| `user_type` / 이용자구분 | `user_type` | 7개 값의 표기가 같다. |
| `sex` / 성별 | `sex` | 3개 값의 표기가 같다. |
| `user_count` / 이용자수 | `user_cnt` | 월별 값. 더하지 않는다. |
| `use_count` / 이용건수 | `use_cnt` | 더할 수 있다. |
| `use_amount` / 이용금액 | `use_amt` | 더할 수 있다. 대조 줄의 기준 값 |
| (없음) | `bjd`, `dstrct_se`, `city`, `week`, `time`, `age`, `tour_type` | 허브에 없는 단위. 주문서의 빈칸이 된다. |

추정의 근거: 센터 카드 시트 아홉 장의 업종 참고표(42행)가 서로 같고 1048 의 업종명과 같다. 이용자구분 7값·성별 3값·수치 3종이 짝을 이룬다. 1048 의 끝 달(2025-06)이 센터 v01 계열(1-07, 1-11, 1-13)의 끝 달과 같다.

확인하지 못한 것: 1048 이 센터 데이터의 도 전체 합계인지 실물로 대조하지 못했다. 허브 화면에는 어느 카드사 표본인지 표기가 없다.

### 9.2 허브 520 ↔ 센터 내국인 유동인구(4-10, 4-11, 4-07)

| 허브 520 | 센터 컬럼 | 대응 |
|---|---|---|
| `base_year_month` | `base_date` | 센터는 일 단위(YYYYMMDD). 앞 6자리가 월이다. |
| `sex` | `sex` | 남성, 여성 |
| `age_range` | `age` | 센터는 2022-06 까지 10세 단위(KT), 2022-07 부터 5세 단위(SKT). 520 은 8개 이름으로 적혀 있다. |
| `time_range` | `time` | 센터 명세서는 01~24시(정각에 잰 값). 520 은 2022-07 부터 00~23시로 적는다. |
| `visit_population_count` | `visit_pop_cnt` | 사람 수가 아니라 체류량에 가깝다. |
| (없음) | `emd_cd`, `emd_nm`, 거주지 구분 등 | 허브에 없는 단위 |

추정의 근거: 520 의 끝 달(2025-04)이 센터 4-10 의 끝과 같다. 시각·성별·연령대·방문인구 축이 겹친다. 520 의 달마다 줄 수(432줄, 672줄)가 4-10 참고표의 연령 구간 수(KT 9구간, SKT 14구간) × 성별 2 × 시각 24 와 맞는다.

확인하지 못한 것: 520 의 값이 센터 `visit_pop_cnt` 를 어떤 범위(거주지 구분 등)로 더한 것인지. 520 과 4-11(v02, 2025-05 시작)은 겹치는 달이 없다.

## 12. 재현 방법

```text
python3 tools/build_spec.py --check        명세서 xlsx → spec.json 변환이 같은지
python3 tools/make_sample_center.py        가상 센터 CSV 3종을 같은 시드로 다시 만들기
python3 -m unittest discover -s tests      전처리·집계·인식·가리기 시험
python3 tools/e2e.py                       시나리오 3개 + CSV 재분석 + 삭제 재현
```

허브 실물 파일이 없는 곳에서 돌려야 할 때만 `python3 tools/make_placeholder_public.py` 로 같은 모양의 대체 파일을 만든다. 대체 파일을 쓰는 동안에는 화면 오른쪽 위에 "공개 데이터: 대체 파일로 계산 중"이 뜬다. 제출본에는 대체 파일이 들어 있지 않다.
