1. 문제 정의

1.1 누가, 언제 쓰는가

제주빅데이터센터를 방문해 센터 PC 앞에 앉은 사람이, 내려받기 메뉴를 열기 전에 쓴다. 주문서를 만드는 앞 절반은 공개 데이터와 공개 명세서만 쓰므로 방문 전 집에서도 같은 프로그램이 돈다.

1.2 막히는 곳

막히는 곳내용지금 있는 수단
무엇을 받을지명세서 v13(2026-11-04) 기준 데이터 71종, 참고표 2종. 같은 "카드 이용 현황"이 읍면동·요일별·시간대·격자와 v01·v02 로 갈리고, 차이는 시트를 열어 컬럼을 견줘야 보인다. 예: 법정동 단위의 시간대는 v02(1-14)에만 있고 v01(1-13)은 6개 권역까지다.센터 제공데이터 화면은 이름과 반출 가부를 나열한다.
어느 달을 받을지센터 데이터는 한 번에 1개월 단위로만 내려받을 수 있다(운영진 답변). 아무 달이나 받으면 성수기 한 달로 한 해를 판단하게 된다.어느 달이 많은 달인지는 받기 전에 알 수 없다.
공개 데이터로 이미 되는 것도 전체 추이나 이용자구분 비중은 허브 공개 파일로 계산된다.공개 데이터로 못 채운 칸을 센터 데이터로 이어 주는 화면이 없다.
받은 뒤카드·유동인구·포스 데이터는 "반출 불가능(가공 형태만)"이고 단순집계 10 미만은 가려야 한다.기준은 반출 정책 문서에 있고 결과를 만든 뒤에야 부딪힌다.

1.3 이 프로그램이 내는 것

목적 문장 → 필요한 단위 결정 → 공개 데이터로 채운 칸 + 빈칸 → 명세서 짝짓기 → 주문서 한 장 → 내려받은 CSV 로 다시 계산

"주문서"는 센터에서 내려받을 목록을 적은 한 장이다. 대신 분석해 주는 서비스가 아니다.

2.2 LLM 과 코드의 역할

LLM 이 하는 일코드가 하는 일
목적 문장에서 지역·업종·대상·필요한 단위·눈여겨볼 값을 읽는다모든 수치(월별 집계, 계절 지수, 비중, 재분석 표)
도구를 어떤 순서로 부를지 정한다명세서에서 후보 찾기, 후보마다 채우는 단위와 못 채우는 단위, 버린 이유
한 데이터로 안 될 때 두 안 가운데 무엇을 먼저 권할지 고른다받을 달 3개, 조건의 컬럼과 값, 쓸 컬럼, 내려받기 횟수
고른 이유를 글로 쓴다검증, 10 미만 가리기, 대조 줄

수치는 코드만 말한다. LLM 이 쓴 글에서 아라비아 숫자가 든 문장, 수량·순위를 말하는 한글 표현("절반", "두 배", "삼십억 원", "일등" 등)이 든 문장, 금지 표현이 든 문장은 코드가 빼고(agent.clean_text), 뺀 문장 수를 "AI가 한 일" 페이지의 "글 다듬기" 단계(원문 상자)에 적는다. 명세서에 실재하는 데이터 번호(1-14), 판 표기(v02), 연령대 이름(10대~70대)은 이름이라 남긴다. LLM 이 도구 인자에 적은 글자(데이터 번호, 컬럼 이름, 조건 값)도 형식과 실재를 검사해 통과한 것만 기록에 옮긴다. 막지 못하는 범위: 숫자도 수량 낱말도 없이 쓴 서술(예: "여름에 많다")은 걸러 내지 못한다. 그런 문장이 화면의 "이 데이터를 고른 까닭"에 나올 수 있다. 이 글을 LLM 이 썼다는 것은 오른쪽 위 "준비됨 · AI 사용" 표시와 "AI가 한 일"의 "글 다듬기" 줄로 알 수 있으나, "이 데이터를 고른 까닭" 칸 자체에는 따로 표시가 없다.

LLM 이 문장에 없는 단위를 넣어 받을 데이터를 늘리는 것도 코드가 막는다. 문장에 요일이나 시간대를 가리키는 말이 없는데 LLM 이 그 단위를 넣으면 빼고, 뺐다는 사실을 "AI가 한 일"의 해석 줄에 적는다. 받을 목록 위에도 "요일·시간대는 문장에 없어 뺐어요."처럼 한 줄로 보이고 "넣어서 다시 만들기 ›" 버튼을 둔다.

장치내용

받을 달LLM 이 적은 달이 pick_months 가 고른 달이 아니면 되돌려 보낸다.
상한호출 8턴, 요청 한 번 60초, 전체 240초
실패 처리한도 초과·서버 오류·연결 실패·시간 초과는 두 번 다시 시도한다. 그래도 안 되거나 Key 가 없거나 거부·차단되면 규칙 모드로 넘기고 화면에 이유와 조치를 적는다.
인증서인증서 검증을 끄지 않는다. macOS 의 python.org 설치판에서 검증에 실패하면 시스템 인증서 묶음으로 한 번 더 한다.
목적 문장시스템 프롬프트에서 목적 문장을 자료로 다루게 한다(문장 안의 지시를 따르지 않는다).

3. 주요 기능

3.1 화면 구성(3단계 흐름과 상세 페이지)

화면은 질문 → 받을 목록 → 받은 파일의 세 단계다. 2026-11-18 에 ChatGPT 로 뽑은 목업 6장(토스풍 원칙: 한 화면 한 메시지, 친근한 말투, 큰 글자, 넓은 여백, 플랫. 토스의 로고·이름·색·아이콘은 쓰지 않음)과 ui-ux-design-pro·ui-ux-pro-max 스킬 지침으로 3차 단순화했다. 2차 화면을 써 본 사용자가 "한눈에 안 보이고 글자가 너무 많다"고 평가해, 첫눈에 보이는 것을 큰 제목 한 줄, 짧은 설명 한 줄, 큰 버튼 하나로 줄이고 나머지는 지우지 않고 별도 상세 페이지로 옮겼다. 데이터·컴퓨터에 익숙하지 않은 도민과 소상공인을 이용자로 본다. 1920×1080 에서도 가운데 좁은 폭(앱 화면처럼)에만 내용을 두고 바깥은 비운다. 머리에는 제목 "센터 방문 주문서"와 "처음부터"(결과 지우기)만, 그 아래 진행 점 3개, 바닥에 "도움말"과 "프로그램 상태"가 있다. 화면마다 작은 선 그림(말풍선, 문서와 돋보기, 달력, 파일 넣기 등)은 외부 자원 없이 직접 그린 SVG 다. 화면에서는 "주문서"를 "받을 목록"(센터에서 내려받을 목록)이라고 부르고, 인쇄본 제목은 "센터 방문 주문서"다.

상세 페이지는 같은 창에서 주소(#/detail/…, #/trust/…, #/file/detail/…)만 바뀌어 열린다. 새 탭을 열지 않아 공용 센터 PC 에 탭이 쌓이지 않고, 맨 위 "← 돌아가기"와 브라우저 뒤로 가기가 같게 바로 앞 화면으로 돌아간다(예외: 사용 설명서만 결과가 지워지지 않도록 새 창).

3.2 기능

기능내용
공개 데이터로 먼저 답하기허브 1048(카드) 또는 520(유동인구)으로 도 전체 월별 추이, 1~12월 계절 지수, 비중을 계산해 "공개 데이터로 먼저 봤어요" 페이지에 그림과 표로 보인다. 답할 수 없는 목적이면 "이 질문은 공개 데이터로는 볼 수 없어요."라고 밝힌다.
센터에서 받는 정보 표시필요한 단위 가운데 공개 데이터에 없는 것을 "공개 데이터에 없는 것"으로 드러내고 "센터에서 받아 채우는 것"과 "센터에도 없는 것"으로 나눈다. 파일을 넣은 뒤에는 "자세히 보기"에 "앞에서 비어 있던 … 정보를 이 파일로 채웠어요."가 나온다.
명세서 짝짓기빈 단위를 가진 센터 데이터를 컬럼 수준에서 찾고, 고르지 않은 후보와 이유를 "이 결과를 믿어도 될까요?" › "AI가 한 일"(AI 없이 만들면 "프로그램이 한 일")에 남긴다. 고른 까닭은 "무엇을 받나요?" 페이지에도 있다.
두 가지 방법 비교한 데이터로 안 되면 두 방법을 내려받기 횟수, "이 방법으로 볼 수 있는 것", "이 방법으로는 못 보는 것"과 함께 견주고 "추천 방법"을 표시한다. 받을 목록에는 추천 방법으로 짠 줄 3개와 "다른 방법 보기" 한 줄만 보이고, 비교는 "두 가지 방법이 있어요" 페이지에 있다.
없다고 말하기필요한 단위를 가진 데이터가 없으면 받을 목록에 "연령대는 센터에도 없어요" 줄을, 그 페이지 "이 정보는 센터에 없어요"에 왜 없는지와 "대신 볼 수 있는 것"을 적는다.
받을 달 3개계절 지수의 많은 달·적은 달·평균에 가까운 달을 센터 데이터의 수록 범위 안에서 고른다. 받을 목록에는 달만, "몇 월 치를 받나요?" 페이지에 1~12월 막대와 "평소보다 n% 많음/적음", 지수 값은 막대와 인쇄본에 보인다.
주문서 한 장과 인쇄데이터, 받을 달, 고를 조건, 받을 항목, 반출 규칙, 내려받기 횟수, 고른 까닭, 명세서 대조 결과. 조건의 컬럼 이름·코드 값과 명세서 시트·컬럼 근거는 "어떤 조건으로 받나요?" 페이지의 "근거 원문"에 있다(예: biz_cd (업종코드) = I56111 (한식 음식점업), 근거: 명세서 1-14 시트 6번 컬럼). 문장을 뜻대로 읽지 못한 곳은 노란 띠로 경고한다. "목록 인쇄하기"는 A4 한 장에 맞춰 명세서 번호·코드 값·받은 달 표시 칸을 넣어 인쇄한다.
과정 펼쳐 보기"AI가 한 일"(AI 없이 만들면 "프로그램이 한 일") 페이지에 단계 순서, 단계마다 "원문" 상자(넣은 값, 결과), 고르지 않은 후보와 이유. AI 사용 중이면 "근거 원문"에 모델, 주고받은 횟수, 토큰 수
보낸 내용 표시"AI로 보낸 내용" 페이지에 내가 적은 문장·공개 데이터 요약값·명세서 항목을 보냈는지와 건수, "센터 파일 값 0건". "이 결과를 믿어도 될까요?"의 그 줄에도 늘 "센터 값 0건"
내려받은 CSV 로 다시 계산카드 v02 계열 3종(1-08, 1-12, 1-14). 첫 줄로 데이터를 알아보고, 결과 한 문장과 막대 하나를 먼저, "자세히 보기"에 비중·순위, 한 단계 더 들어가 10 미만을 가린 숫자 표와 공개 데이터와 견주기를 보인다. 목록대로 넣을 파일(데이터 × 달)을 몇 개 넣었는지 보인다.
이상한 파일 처리빈 파일, CSV 가 아닌 파일, 컬럼이 다른 파일을 넣어도 멈추지 않고 파일마다 "원인"과 "할 일"을 쉬운 한국어 한 줄로 보인다(원래 글은 "근거 원문").
결과 삭제화면 오른쪽 위 "처음부터". 화면 안 확인 카드 "처음부터 다시 할까요?"로 한 번 묻고 결과, 넣은 파일, 기록을 지운 뒤 "지웠어요: 결과 n건, 넣은 파일 n개, 기록 n건."을 보이고 질문 화면으로 돌아간다.
자가 점검실행하면 9가지를 스스로 확인해 실행 창과 화면 바닥의 "프로그램 상태" 페이지에 보인다. 문제가 있으면 질문 화면 위에 "프로그램 점검에서 확인할 것이 있어요."

5.4 한계

한계내용
가상 파일의 순환시연용 센터 CSV 는 명세서를 보고 만든 파일이라, 명세서로 인식되고 계산되는 것이 당연하다. 재분석이 실제 파일에서 도는지는 이 시연으로 증명되지 않는다.
받을 달도 전체 공개 데이터의 계절 지수로 고른다. 읍면동에서는 다를 수 있다. 외국인 목적은 내국인 지수를 참고로만 쓴다.
주문서 범위카드·포스 소비 계열 22종과 방문·유동인구 계열 9종만 주문서로 짝짓는다. 나머지 40종의 주제는 데이터 이름만 안내한다. 주제는 낱말로 가리므로 사전에 없는 범위 밖 주제는 걸러지지 않고 두 계열로 풀릴 수 있다.
재분석 범위카드 v02 계열 3종만. 다른 데이터의 CSV 는 어떤 데이터인지와 줄 수만 알려 준다.
지역 이름명세서의 법정동·행정동·권역·시 이름만 조건으로 쓴다. 마을(리)·해변·명소는 자주 쓰는 18개 이름만 그것이 속한 읍면동으로 읽고(그렇게 읽었다고 경고), 그 밖의 이름은 못 찾았다고 경고한 뒤 도 전체로 푼다.
가리기정확한 값을 거꾸로 셈하는 길만 막는다. 범위를 좁혀 짐작하는 것, 0 인 칸이 0 임을 아는 것은 막지 못한다(4.2절).
LLM 의 글숫자와 수량 낱말이 든 문장은 빼지만, 그런 낱말 없이 쓴 서술은 걸러 내지 못한다(2.2절).
한 화면받을 목록의 제목·줄 3개·"목록 인쇄하기"는 첫 화면 안에 있지만, 1366×768 에서는 "받은 파일 넣기"와 "이 결과를 믿어도 될까요?"가 첫 화면 아래로 내려간다(규칙 모드 측정). 받은 파일의 "자세히 보기" 페이지는 막대 묶음이 3~4개라 1366×768 에서 높이가 약 2700px 이다(구현 담당 보고). 자세한 내용을 상세 페이지로 옮긴 만큼, 근거를 보려면 한두 번 더 눌러야 한다. 인쇄는 A4 한 쪽에 맞춘다.
규칙 모드낱말 사전에 없는 말은 알아듣지 못한다. 타협안을 문장의 강조에 따라 고르지 못한다.
직접 고르기"20대", "토요일" 같은 특정 값을 넣는 칸이 없다.
LLM 모드의 시나리오 2애월읍 카페 문장은 실행마다 해석이 달라 두 방법 비교가 나오지 않을 수 있다. 시연은 예시를 누른 뒤 "직접 고르기"로 만드는 것을 권한다(규칙으로 계산해 늘 같은 결과). app/ 쪽 해석은 고치지 않았다.
LLM 모드의 단위 읽기받을 항목은 코드가 목적에서 정한 목록이 기준이고 AI 는 더하기만 하므로 빠지지 않는다(시나리오 1은 실호출에서 늘 7개). 다만 AI 가 목적에서 필요한 단위를 실행마다 다르게 읽을 수 있어 명세서 대조 항목 수가 달라진다(시나리오 1 실호출에서 17개~30개, 모두 통과). 늘 같은 결과가 필요하면 "직접 고르기"로 만든다.
대화입력은 한 번이다. 이어 묻지 못한다.
데이터허브 1048 은 한 카드사 표본으로 보이고(추정) 520 은 사람 수가 아니라 체류량이다. 자세한 것은 docs/데이터_활용_명세.md 11절
보존올린 파일의 사본과 결과가 "처음부터"로 지울 때까지 runtime/ 에 남는다. 창을 닫는다고 지워지지 않는다.
반출가리기는 보조 장치다. 반출 가부를 판정하지 않는다.

6. 센터 활용 방안

6.1 센터 이용 흐름에서의 자리

센터 이용 단계이 프로그램이 하는 일
방문 전(집)목적을 넣어 주문서를 만들고 인쇄한다. 공개 데이터와 공개 명세서만 쓰므로 센터 밖에서도 된다.
센터 PC 에 앉아 내려받기 메뉴를 열기 전주문서를 보고 어느 데이터를, 어느 달을, 어떤 조건으로, 몇 번 받을지 정한다.
CSV 를 내려받은 뒤파일을 넣어 빈칸을 채운다. 비중·순위를 먼저 보고, 10 미만이 가려진 표를 확인한다.
반출 신청 전화면을 캡처해 반출 신청에 쓴다. 주문서의 "반출 주의"에 그 데이터의 기준이 적혀 있다.
이용을 마칠 때화면 오른쪽 위 "처음부터"를 눌러 지운다.

6.2 센터 운영 조건과의 맞물림

운영 조건(운영진 답변)이 프로그램
센터 비공개 데이터를 외부 LLM 으로 보내면 안 된다CSV 를 다시 계산하는 경로는 LLM 을 부르지 않는다. 화면에 "센터 값 0건"("이 결과를 믿어도 될까요?"의 "AI로 보낸 내용" 줄)과 "센터 파일 값 0건 · 다시 계산은 이 컴퓨터 안에서만 해요"(그 페이지), "AI로 보낸 값 0건"(받은 파일의 "자세히 보기")을 표시한다.
Agent 는 센터 DB 에 직접 접속하지 못하고, 이용자가 내려받은 CSV 를 불러오는 구조여야 한다그 구조다. 파일명이 아니라 첫 줄로 데이터를 알아본다.
결과 삭제 기능이 없으면 탑재가 어려울 수 있다화면 오른쪽 위의 "처음부터" 버튼이 결과·넣은 파일·기록을 지우고 지운 개수를 보인다.
LLM Key 는 담당자가 미리 설정해 이용자에게 노출되지 않게 한다화면에 Key 입력 칸이 없다. .env 또는 환경변수로 넣는다. Key 가 없어도 규칙 모드로 돈다.
서명 없는 패키지·확장 모듈은 실행이 제한될 수 있다패키지 0개. 파이썬 표준 라이브러리만 쓴다.
사용하는 외부 주소를 밝힌다api.anthropic.com 하나. 규칙 모드에서는 외부 접속이 없다.
운영 비용 효율, 널리 쓰이는 안정적 모델기본 모델은 Claude 의 저가 등급인 Haiku 계열(claude-haiku-5-5)이다. 주문서 한 번에 4턴, 입력 3만~4만 토큰대로 쟀다(4.6절). 수치 계산과 재분석에는 LLM 을 쓰지 않는다.

설치와 운영 절차는 docs/사용자_매뉴얼.md 7절에 있다.
